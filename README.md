# CodeTask Tracker 0.1.0

Лабораторная работа №3: расширение VS Code для задач в комментариях.
Тема согласована. Разработка ведётся отдельными проверяемыми этапами.

## Что работает сейчас

- Команда **CodeTask Tracker: Найти задачи в текущем файле** ищет задачи в C/C++.
- Поддерживаются `TODO`, `FIXME`, `BUG`, `HACK`, `NOTE`.
- Приоритеты: `HIGH`, `MEDIUM`, `LOW`; без указания используется `MEDIUM`.
- Результаты показываются в панели **Output → CodeTask Tracker**: строка, столбец,
  тип, приоритет и описание. Нумерация строк и столбцов начинается с 1.
- Читается текущий текст редактора, включая несохранённые правки.
- Команда **CodeTask Tracker: Проверить запуск** сохранена для первого знакомства.

- В **Explorer → CodeTask Tracker** есть дерево «файл → задачи».
- Нажатие на задачу открывает файл и выделяет метку на нужной строке.
- Список обновляется после правок, создания, удаления и переименования файлов.
- В заголовке панели есть кнопка обновления; команда **CodeTask Tracker: Обновить задачи проекта**
  выполняет тот же поиск. Поддерживаются проекты с несколькими корневыми папками.

- Фильтры по типам, приоритетам, пути файла и тексту задачи применяются вместе.
- Кнопка сброса возвращает все найденные задачи.

Основные пять функций лабораторной реализованы для C/C++.
Готовый пакет: `code-task-tracker-0.1.0.vsix`. Подготовка к защите: [памятка](docs/DEFENSE.md).

## Установка готового расширения

Требуется VS Code **1.144.0 или новее**. Node.js для установки готового VSIX не нужен.

1. Откройте Extensions (**Cmd+Shift+X**).
2. В меню `…` выберите **Install from VSIX…**.
3. Выберите `code-task-tracker-0.1.0.vsix`.
4. Если редактор предложит перезагрузить окно, согласитесь.
5. Откройте папку с C/C++ файлами и раздел **CodeTask Tracker** в Explorer.

Пакет устанавливается локально. В Marketplace расширение не опубликовано;
идентификатор локального пакета — `davakapa.code-task-tracker`.

## Боковая панель

В VS Code откройте папку с C/C++ файлами (**File → Open Folder**),
затем Explorer (**Cmd+Shift+E**) и раздел **CodeTask Tracker**.
Например, можно открыть папку `examples` из этого репозитория.
Файл раскрывается в список задач; у каждого типа свой значок и цвет,
а приоритет написан явно. Нажмите задачу для перехода к метке.

После серии правок поиск запускается через 300 мс. Новое сканирование отменяет
публикацию старого результата. Если пункт устарел до нажатия, расширение обновит
список и предложит выбрать задачу снова. Отдельные несохранённые файлы без пути
в проекте не входят в дерево — для них остаётся команда поиска текущего файла.

Поиск рассматривает расширения `.c`, `.h`, `.cc`, `.cpp`, `.cxx`, `.hpp`, `.hh`,
`.hxx`, `.C`, `.H` и режимы языка C/C++.
Исключены каталоги `.git`, `node_modules`, `out`, `dist`, `build`, `.vscode-test`.
За один поиск обрабатывается до 1000 файлов, файлы больше 1 МиБ пропускаются.
При ограничении или пропусках панель показывает предупреждение; подробности
ошибок чтения попадают в Output → CodeTask Tracker. Это не поиск по всему диску:
область поиска ограничена открытыми папками проекта.

## Фильтры и поиск

В заголовке **CodeTask Tracker** находятся кнопки:

- **Настроить фильтры** (воронка): тип задачи, приоритет, имя/путь файла или текст.
- **Поиск по тексту задачи** (лупа): быстрый ввод части описания.
- **Сбросить фильтры**: убрать все ограничения.
- **Обновить задачи проекта**: повторно прочитать файлы, сохранив условия.

Те же команды доступны через Cmd+Shift+P с префиксом `CodeTask Tracker:`.

Типов и приоритетов можно выбрать несколько. Внутри одного списка подходит
любой выбранный вариант; разные условия должны выполняться одновременно.
Например: тип `TODO` или `BUG`, приоритет `HIGH`, файл содержит `src/`,
описание содержит `проверить`.

Путь и текст ищутся как обычная подстрока без учёта регистра. Это не glob
и не регулярное выражение: `*`, `.` и квадратные скобки трактуются буквально.
Путь отсчитывается от папки проекта; при нескольких корнях учитывается и имя корня.
Текстовый поиск проверяет описание задачи, а тип и приоритет задаются своими фильтрами.

Чтобы снять одно условие, очистите текстовое поле или снимите все галочки
в соответствующем списке и подтвердите ввод. Escape отменяет изменение.
В панели показаны включённые условия и число видимых задач из общего количества.
Если совпадений нет, это явно указано; пустые группы файлов скрываются.

Фильтры действуют на боковую панель, а команда поиска текущего файла в Output
по-прежнему показывает все задачи файла. Условия сохраняются при обновлении и
изменениях исходников, но сбрасываются при перезапуске расширения/окна VS Code.

## Формат комментариев

```cpp
// TODO[HIGH]: проверить входные данные
int x = 0; // FIXME: исправить значение
/* NOTE[LOW]: пояснить решение
 * BUG: обработать пустой массив
 * HACK: временная реализация
 */
```

Одна задача на строку комментария. Метка стоит в начале текста комментария,
регистр — верхний, двоеточие и непустое описание обязательны.
Неизвестный приоритет (например, `[URGENT]`) не считается задачей.
Обычные строки, символьные литералы и raw strings C++ пропускаются.

Начальный парсер поддерживает C/C++. Другие языки пока отклоняются явно.
Это поиск по исходному тексту, без препроцессора: комментарии внутри `#if 0`
тоже учитываются. Склейка строк через обратную косую черту перед переводом
строки и старые триграфы C пока не поддерживаются; в таких файлах результаты
могут быть неточными. Отдельно расширим правила, если эти случаи понадобятся.

Для примера откройте `examples/tasks.cpp` и выполните команду поиска:
ожидается **5 задач**, строка с текстом `// BUG` внутри кавычек пропускается.

## Запуск из исходников

- Node.js 24 LTS с npm.
- VS Code 1.144.0 или новее (версия, выбранная генератором).
- Git.

```sh
npm ci
npm run compile
code .
```

Откройте `src/extension.ts`. Нажмите F5 (на Mac при необходимости Fn+F5)
или выберите **Run → Start Debugging**. В отдельном окне Extension Development Host
нажмите Cmd+Shift+P и выполните **CodeTask Tracker: Проверить запуск**.
Ожидаемый результат — уведомление «CodeTask Tracker запущен!».

Сборка перед запуском выполняется задачей `npm: compile`.
Для обновления после правок остановите отладку и снова нажмите F5.

## Как устроен первый этап

- `package.json`: имя, требования, команды расширения и команды сборки.
  `contributes.commands` объявляет команду для палитры.
- `src/extension.ts`: `activate` регистрирует обработчик команды.
  `showInformationMessage` показывает уведомление.
  `context.subscriptions` позволяет VS Code освободить обработчик при отключении.
- `tsconfig.json`: настройки TypeScript.
- `esbuild.js`: собирает исходники в `dist/extension.js`.
- `.vscode/launch.json`: запускает отдельное окно для отладки.
- `.vscode/tasks.json`: описывает сборку перед отладкой.
- `package-lock.json`: фиксирует зависимости для воспроизводимой установки.

`dist`, `out` и `node_modules` не хранятся в Git: они создаются при установке и сборке.

## Проверка и упражнение для защиты

`npm run compile` проверяет типы, запускает ESLint и собирает расширение.
`npm run test:unit` запускает проверки парсера и фильтров без VS Code.
`npm test` проверяет команду в отдельном VS Code (при первом запуске может скачать редактор).
На Mac с установленным редактором можно использовать его:

```sh
VSCODE_EXECUTABLE="/Applications/Visual Studio Code.app/Contents/MacOS/Code" npm test
```

Парсер находится в `src/taskParser.ts` и не зависит от VS Code.
Он проходит по тексту, пропускает строки и читает комментарии. Регулярное выражение
разбирает только строку комментария: тип, необязательный приоритет и описание.
`offset` хранит позицию метки; `document.positionAt(offset)` получает строку и столбец.
Команда из `src/extension.ts` связывает парсер с текущим редактором и панелью вывода.

Поставьте точку останова на `showInformationMessage`, запустите расширение
и вызовите команду. Объясните, почему ID в `registerCommand` совпадает с ID
в `package.json`. Затем измените текст уведомления и повторите запуск.


## Как устроена панель

`src/taskTree.ts` содержит `TaskTree`, реализацию `TreeDataProvider`:

- `refresh()` находит файлы, читает текст и вызывает готовый `parseTasks`.
- `getChildren()` отдаёт корневые файлы или задачи выбранного файла.
- `getTreeItem()` задаёт подпись, значок и команду нажатия.
- `openTask()` проверяет актуальность позиции, открывает файл и выделяет метку.
- `onDidChangeTreeData` сообщает VS Code, что дерево нужно перерисовать.

`src/extension.ts` регистрирует панель, команды и наблюдатели за изменениями.
Все подписки передаются в `context.subscriptions` для освобождения ресурсов.

На защите можно показать `examples/tasks.cpp`, добавить `// TODO: новая задача`,
увидеть обновление дерева и перейти к строке. Объясните отличие данных задачи
(`TaskNode`) от её отображения (`TreeItem`).


## Как устроены фильтры

- `src/taskFilters.ts`: структура условий и чистая функция `matchesFilters`.
  Она принимает задачу, путь и условия, возвращает `true` или `false`.
- `src/filterCommands.ts`: стандартные диалоги VS Code, выбор нескольких вариантов,
  ввод текста и обработка отмены.
- `TaskTree` хранит полный список отдельно от видимого. Метод `updateView()`
  фильтрует задачи и убирает пустые группы, сохраняя исходные позиции для перехода.

Для защиты: выберите `BUG` в примере — останется одна задача; добавьте `LOW` —
совпадений не будет; сбросьте фильтры — снова пять задач. Объясните, почему
фильтрация не должна удалять элементы из полного списка.

Версия 0.1.0 подготовлена на macOS ARM64, Node.js 24.22.1 и VS Code 1.144.0.
Автоматические проверки: 18 тестов парсера/фильтров и 17 интеграционных сценариев.
Проверяются несохранённые правки, дерево, навигация, изменения файлов, несколько
папок, сочетания фильтров, сброс и отмена диалогов. Готовый VSIX установлен в отдельный профиль VS Code: все 17 интеграционных
сценариев также прошли на установленном пакете; проверено совпадение его JavaScript
с production-сборкой. Windows и Linux отдельно не проверялись.
