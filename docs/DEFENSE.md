# CodeTask Tracker — памятка для защиты

## Что сказать о проекте

«Я разработал расширение VS Code на TypeScript, которое собирает задачи из
комментариев C/C++. Оно понимает TODO, FIXME, BUG, HACK и NOTE, показывает
приоритеты, группирует задачи по файлам, открывает нужную строку и фильтрует
результаты. Изменения файлов автоматически обновляют список».

Заготовка создана через Yeoman с generator-code; сборка — esbuild.
При работе использовалась помощь ИИ. На защите важно самостоятельно объяснить
код, его ограничения и предложенные ниже изменения.

## Демонстрация за 3–5 минут

1. Установить VSIX и открыть папку `examples` из репозитория.
2. Открыть Explorer → CodeTask Tracker. В `tasks.cpp` должно быть **5 задач**.
3. Показать `TODO[HIGH]` и `FIXME` без приоритета: для второго используется MEDIUM.
4. Нажать BUG: откроется строка с меткой. Строка `"// BUG: ..."` внутри кавычек
   не попадает в список.
5. В фильтрах выбрать BUG — останется одна задача. Добавить LOW — совпадений нет.
   Сбросить фильтры — снова пять задач.
6. В поиске по тексту ввести `проверку` — найдётся TODO; затем сбросить фильтры.
7. Добавить строку `// NOTE[LOW]: показать на защите` и подождать примерно 300 мс.
   Задача появится даже до сохранения. Удалить строку — задача исчезнет.
8. Показать Git-историю и тесты. Каждый коммит соответствует реально завершённому этапу.

## Карта кода

| Файл | За что отвечает |
| --- | --- |
| `package.json` | Описание расширения, команды, панель и кнопки, сборка и зависимости |
| `src/extension.ts` | Запуск расширения, регистрация команд и подписок |
| `src/taskParser.ts` | Читает исходный текст и находит задачи внутри комментариев |
| `src/taskTree.ts` | Читает файлы проекта, строит дерево и открывает нужную строку |
| `src/taskFilters.ts` | Проверяет, подходит ли задача под заданные условия |
| `src/filterCommands.ts` | Показывает диалоги выбора типов, приоритетов и текста |
| `src/test/*.unit.ts` | Тесты парсера и фильтров без запуска редактора |
| `src/test/*.test.ts` | Проверки команд и дерева внутри настоящего VS Code |
| `esbuild.js` | Собирает TypeScript в один JavaScript-файл `dist/extension.js` |

## Как проходит одна задача через программу

Исходная строка:

```cpp
// TODO[HIGH]: проверить входные данные
```

1. Парсер обнаруживает `//` и читает комментарий до конца строки.
2. Регулярное выражение выделяет тип TODO, приоритет HIGH и описание.
3. Создаётся `CommentTask`: `type`, `priority`, `message`, `offset`.
4. `offset` — позиция буквы T от начала всего текста. Это не номер строки.
5. `document.positionAt(offset)` превращает позицию в строку и столбец VS Code.
6. Задача помещается в группу её файла. Фильтр решает, нужно ли её показывать.
7. `getTreeItem()` создаёт подпись, значок и команду нажатия.
8. `openTask()` проверяет актуальность и выделяет метку в редакторе.

В API строки и столбцы начинаются с нуля. Для подписи пользователю прибавляем 1.
Позиции строк JavaScript и VS Code измеряются в кодовых единицах UTF-16,
поэтому `offset` из JavaScript подходит для `positionAt`.

## Вопросы, на которые нужно уметь ответить

**Что делает activate?** Регистрирует команды, панель и обработчики событий.
VS Code вызывает её при обращении к расширению.

**Зачем context.subscriptions?** VS Code вызовет `dispose()` у этих объектов при
отключении расширения: уберёт команды, наблюдатели и обработчики событий.

**Чем getChildren отличается от getTreeItem?** Первый отвечает за структуру
данных: какие узлы находятся внутри. Второй описывает внешний вид одного узла.

**Зачем регулярное выражение, если уже есть цикл по тексту?** Цикл различает
код, комментарии и строки. Регулярное выражение разбирает только содержимое
комментария. Поиск TODO регулярным выражением по всему файлу дал бы ложные
задачи внутри строк.

**Как пропускаются строки?** Обычные кавычки читаются до закрывающей, с учётом
обратной косой черты. У C++ raw string находится собственный завершающий
разделитель. Разделитель цифр в `1'000` не принимается за символьный литерал.

**Откуда берутся несохранённые изменения?** `openTextDocument` возвращает уже
открытый документ. `getText()` берёт актуальный текст из редактора.

**Зачем задержка 300 мс?** Чтобы серия нажатий не запускала полный поиск после
каждой буквы. Новый ввод перезапускает таймер — это debounce.

**Что делает generation?** Это номер запроса обновления. Если во время поиска
пришла новая правка, старый запрос перестаёт публиковать свой результат.
Это защита от ситуации, когда старые данные заменяют новые.

**Почему полный список хранится отдельно?** Фильтры должны только скрывать
задачи. После сброса нужно вернуть исходный список без повторного чтения файлов.

**Как сочетаются фильтры?** Тип TODO или BUG — логическое ИЛИ внутри списка.
Тип плюс приоритет плюс файл плюс текст — логическое И между условиями.

**Почему нельзя просто перейти к сохранённой строке?** Пользователь мог
изменить текст. Перед переходом задача перепроверяется; если данные устарели,
список обновляется и предлагается повторить выбор.

**Почему TypeScript, если VS Code запускает JavaScript?** Типы проверяются
при разработке. При сборке они удаляются, а esbuild создаёт JavaScript-пакет.
Модуль `vscode` не включается в пакет: его предоставляет сам редактор.

## Небольшие изменения для тренировки

### Изменить приоритет по умолчанию

В `taskParser.ts` найти `match[2] ?? 'MEDIUM'`. Изменить на LOW и поправить
ожидаемые значения соответствующих тестов. Явный `[HIGH]` должен остаться HIGH.
После упражнения вернуть MEDIUM.

### Добавить тип REVIEW

Изменить тип `TaskType`, регулярное выражение парсера, список в диалоге типов
и таблицу значков. Добавить тест для `// REVIEW: проверить решение`.
Компилятор поможет найти забытые места, где используется `Record<TaskType, ...>`.

### Сделать поиск чувствительным к регистру

В `matchesFilters()` убрать `.toLowerCase()` у текста и запроса. Обновить тест,
который сейчас проверяет совпадение разных регистров, и документацию.

### Скрыть низкий приоритет по умолчанию

Изменить `defaultFilters()` на список HIGH и MEDIUM. Обсудить, должен ли сброс
показывать все задачи или возвращать новый набор по умолчанию.

После каждого изменения запускать `npm run compile`, `npm run test:unit`
и затронутые интеграционные проверки. Сохранение `.ts` само по себе не меняет
уже собранный `dist/extension.js`.

## Честные ограничения версии 0.1.0

- Поддерживаются C/C++ и указанные в README расширения файлов.
- Одна задача на строку комментария; метки и приоритеты пишутся верхним регистром.
- Требуются двоеточие и непустое описание.
- Не выполняется препроцессор; задачи внутри `#if 0` тоже видны.
- Склейка строк обратной косой чертой и старые триграфы C не поддерживаются.
- Поиск ограничен 1000 файлами; крупные файлы пропускаются с сообщением.
- Фильтры не сохраняются после перезапуска расширения.
- Группировка реализована по файлам; отдельной группировки по типу/приоритету нет.

Это границы реализации, а не повод обещать поддержку непроверенных случаев.
